## 作業ルール（所有者の指示と、これまでの決まり）
- ブランチは `master` から切り、段階ごとに PR を 1 本出す（先の段階は前の段階のブランチの上に積んでもよい。所有者が番号の小さい順にマージする）。
- 実装・生成物（`evidence/`）・ドキュメントは別コミットに分ける。各段階で次を行う：テストを追加して `scripts/test-current.mjs` に登録、`npm run typecheck`、`npm run test:ci`（と可能なら `npm test`）、スクリーンショットの証跡、`docs/GTA-FIDELITY-STATUS.md` に §9an 以降で記録、push、PR。PR 本文は `.github/pull_request_template.md` の見出しに従う。
- `src/` に実在の銃の名前・メーカー名を書かない（`tests/name-guard.test.mjs` で検査される）。
- 攻撃が当たったときの手応えとして、**カメラの揺れとコントローラーの振動は追加しない**（所有者の指示）。
- ライトを新しく足さない（点光源を増やすと全マテリアルが再コンパイルされる。§16a）。光って見えるものは発光・加算合成で表現する。
- 見た目の確認と性能の確認は、ビルドの成功とは別の関門。完了扱いにしない。

## 環境についての注意（ヘッドレス撮影）
- `npm run dev:local` で開発サーバー（通常 `http://127.0.0.1:5174`）。`?qa=1` で `window.__SHIBUYA_*__` のフックが出る。
- クラウドのヘッドレス Chrome（SwiftShader）では、シーンは約 0.1 fps。段階1の撮影では HIGH と MEDIUM で射撃中に WebGL のコンテキストが失われた（原因は未特定。同じモジュールのベンチでは起きない）。証跡は `qa/gta-upgrade/*bench.html` と `qa/gta-upgrade/weaponbench-capture.mjs out.png "" <bench>.html` のベンチ撮影が確実。`qa/gta-upgrade/` は git-ignore されているので、新しいベンチやスクリプトは `git add -f` で追加する（既存のベンチもそうしている）。シーン撮影は `qa/gta-upgrade/stage1-scene.mjs` が雛形。
- 撮影の実行中にアプリが import しているファイルを編集しない（HMR でページが再読み込みされ、撮影が壊れる）。
- `pkill -f <パターン>` は自分のシェルに一致して終了コード 144 で落ちることがある。PID を指定して止める。
